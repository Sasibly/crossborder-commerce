# 卖家订单首版完善

本轮先处理历史快照、模拟与缺失数据、收货信息权限三项，再完善列表、详情、待处理提醒及时间线。保持现有八分区导航、单商家 US/USD、模拟交易和既有状态机；不接真实物流、不生成真实清关资料。

## 设计

沿用工作台深海蓝标题、青色来源标记、浅蓝底色和系统中文字体。采用紧凑订单卡片配按需展开详情；比较过整页大表与抽屉，前者小屏难读，后者会割裂现有表单与角色逻辑，因此保留原地展开。列表中的状态带与时间轴分别编码“当前要处理什么”和“已经发生什么”，不作为装饰。

- 列表：订单号、创建时间、历史商品摘要/SKU/数量、小计/订单总额与币种、脱敏收件人及地区、状态、退款审核提醒、原操作入口。
- 详情：基本信息、下单商品明细、金额构成、模拟支付记录、模拟履约、按权限单独读取的收货信息、售后、时间线、脱敏来源快照。
- 成交名称和单价只读订单明细快照；完整地址只读下单地址快照，不回查当前商品或地址簿。
- 服务端对摘要、完整列表、state、普通详情统一移除完整地址及订单访问令牌；仅同租户 owner/operator 可访问独立 delivery 接口，viewer 仍可看脱敏详情。买家仅可查询自己的原有订单。
- 运单和支付事件明确为本地模拟标识；无来源的电话、承运商、预计送达、优惠或时间显示未提供/未记录。零金额与未知值分别处理。卖家支付费/物流成本与买家应付金额分开展示。
- 新交易在原事务中追加无个人信息的订单审计。旧订单时间线读取现有审计、库存流水和退款记录，不回填/重写历史；缺失时间和执行者不补造，同秒顺序仅作阶段展示。

## 验证

验证快照在当前商品/地址变动后仍稳定；地址在 viewer、跨租户、匿名、列表/state/详情和买家边界下不会越权泄露；未记录值不变零；重复支付/状态请求不重复记录事件。前端覆盖转义、待处理提示、详情重试、手机布局与原履约/退款操作。部署前备份，部署后比对历史记录和模型预算；实际结果另行记录。

## 日常操作与边界

进入“订单与售后”→“订单查询与履约”，通过状态/时间筛选定位订单。列表中的待支付、待发货和退款待审核标记帮助定位任务；退款审核中不提供发货操作，可直接进入售后申请。

展开“查看订单详情”只发起订单读取，不重新分析评论或修改订单。owner/operator可点击“查看完整收货信息”读取下单地址；viewer的普通详情中没有地址读取入口，直接调用delivery接口也返回403。跨店铺返回404，未认证的受保护实例返回401。当前本机仍为关闭Key校验的owner演示模式，角色边界在独立受保护测试中验证；没有改变本机的登录配置。

完整地址接口返回 `Cache-Control: no-store`。修改卖家Key会立即清空已加载的订单卡片及地址、使旧的异步读取失效；点击“刷新订单”或“加载工作台”后再按新身份读取。没有将完整地址、电话或令牌新增到审计记录、浏览器存储或来源快照展示中。

物流成本框预填下单假设供确认，不能把空值当0提交；明确无成本才输入0。物流单号和支付事件号均为本地模拟标识。电话、承运商、预计送达和签收记录在本轮未新增采集；没有数据时显示未提供/未记录。完成订单不等于真实承运商签收。优惠金额未记录，不自动当作零。

旧订单的事件来自已有审计/库存流水/售后记录，未回填缺失日期或执行者；同秒记录按阶段呈现。最近记录时间指当前详情中所列事件的最近时间，不代表所有后台记录的更新时间。发货、支付和退款仍沿用原状态流转，当前没有新增拆包、清关、税号、HS编码或退货运单流程。
