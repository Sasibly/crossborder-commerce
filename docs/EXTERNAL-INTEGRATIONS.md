# 真实支付与物流的接入边界

> 2026-11-25 更新：按照用户要求，当前所有供应商/服务商交互继续采用模拟。本文仅保留未来可选接入的边界说明，不作为后续开发的凭证前置条件。当前规范见 DATA-SOURCES-POLICY.md。

当前没有绑定服务商，也没有接收真实资金。本文件定义现有业务接口如何被服务商适配层调用，不宣称已完成外部接入。

## 支付

现有入口为 `commerce.pay(conn, tenant, order_id, Payment)`，金额为整数 USD 分，Payment 包含唯一 event_id、amount_cents、currency。现有 owner 端点只用于模拟操作，不能直接把它开放为公网 webhook。

实际接入需要先创建服务商订单并保存外部支付 ID，服务端使用所选服务商 SDK 验证签名、原始请求体和时间窗，再将外部事件映射到内部订单。站点、租户、币种、金额及事件唯一性都由服务端核对，前端跳转不能直接确认支付。支付成功晚于库存释放时，不能直接恢复已取消订单，需要对账及退款/人工处理分支。

真实退款必须先记录请求、调用服务商退款接口，再以经过验证的结果推进状态；当前同步模拟退款逻辑不能充当真实退款对账。

## 物流

现有 Shipment 只接受模拟 tracking 和整单记录物流成本，不会向承运商发单或查询轨迹。真实适配层需要处理 US 地址核验、报价有效期、外部运单 ID、费用币种、轨迹事件去重和异常补偿，再调用内部状态转换。

## 接入所需条件

目标服务商、沙箱账号/密钥、webhook 验签配置、可回调测试地址及其官方接口文档。凭证只通过环境或秘密管理注入，不写进源码、演示脚本或审计记录。服务商确定后按官方文档实现及验证；在此之前不编造 webhook 协议、认证方式或费用规则。
