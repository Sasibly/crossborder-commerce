# 简历与面试材料（以当前实现为边界）

## 项目介绍

跨境选品与经营一体化系统｜个人项目。面向 US 独立站卖家的演示系统，将竞品评论证据、SKU 成本决策、商品管理、多商品订单、模拟支付履约与售后复盘串联。单商家、US/USD、SQLite/FastAPI 单体部署；支付和物流均为模拟。

## 可用于简历的表述

- 集成百炼Qwen3.5-Flash进行逐条结构化抽取，独立管理评论模型与模拟交易执行模式；通过持久化请求预算、幂等任务、原文证据校验、版本缓存及来源快照支持失败追溯。真实调用分析的是合成评论，未接入真实供应商。
- 将10条评论串行改为最多3条并发；两轮真实调用的管道中位耗时由历史13.045秒降至6.143秒，观察到下降52.91%。这是不同时间的小样本对比，不是生产SLA或模型准确率。
- 建立固定验收范围和统一本机验收入口，覆盖六品类200条既有语料回归、权限/缓存契约、六行订单的支付发货退款、在线备份新库恢复及重启持久性；区分有限质量基线、合成标注草案和真实业务能力，失败及未执行阶段分别留痕。

- 设计“评论机会—候选 SKU—版本化决策—商品—订单明细”的追溯链路，分别保存决策、售价、成本、汇率和地址快照，区分 Amazon/FBA 与独立站费用口径。
- 实现服务端购物车和多商品原子下单，通过 SQLite 写事务、条件更新、库存流水与幂等键处理并发和重试，验证 12 个请求争抢 3 件库存时无超卖。
- 实现买家会话、订单所有权与 CSRF 校验，覆盖跨买家订单访问、地址盗用、重复支付通知和不合法状态转换；使用周期任务自动释放超时库存。
- 建立整单售后审核及退款净损失记录，将模拟经营结果与预测贡献利润关联，并实现包含 WAL 数据的在线备份与新库恢复演练。
- 实现本地模拟供应商状态流与指标来源台账，区分公开销售额退货占比和模拟单件退货概率；将可幂等保存的场景计算、成本假设与来源版本快照传递到决策和商品草稿，防止聚合统计误用于 SKU 售后成本。
- 实现同候选两份模拟报价的五种利润敏感性情景，单独展示 MOQ/交期和批量货值；显式采用时校验完整参数与报价版本，将比较依据追溯到订单，保留旧决策和商品快照。
- 建立独立临时库的真实本机 HTTP 基线与恢复演练，以表内容摘要、业务校验及买家订单追踪验证恢复；发现并修复备份连接未及时关闭的问题，提供隔离预部署配置和自动检查。测量边界与原始证据见 OPERATIONS-READINESS.md，不能表述为生产 QPS 或异机灾备已验收。
- 将工作台30单列表的领域SQL从62条降至4条，新增约13KB摘要与按需完整来源；采用单进程每库写事务准入减少竞争，在相同本地负载下观察到8并发三请求流程P95从1041ms降到217ms。保留完整接口兼容、原始报告和测量限制，不能外推为线上收益。
- 在证书链/主机名验证开启的本地HTTPS服务中验证会话、CSRF与支付退款权限，并将Windows业务快照恢复到Linux隔离容器验证内容与新交易。范围是本机跨环境恢复，未声称异机灾备。

当前演示脚本与架构图见 COMMERCE-DEMO.md，本轮可核查算例和新增 8 项测试范围见 PROFIT-COMPARISON-VALIDATION.md。

测试总数包含继承自原选品项目的用例，不能把全部测试声称为本轮新增。旧V1六品类200条固定集F1=0.6070；只为宠物饮水机启用V2后，同一负面标签口径总体F1=0.6090，饮水机20条为0.8750。其他五类仍有明显漏报/误报，不能当作真实模型或经营效果。24扩展标签尚为标注草案、50单元AI参考候选未经人工批准，不得写成24标签已上线或模型准确率100%。没有真实 GMV、支付成功率、真实买家转化率或线上 QPS 可报告。

当前本机启动与统一验收命令：`local-commerce.cmd deploy`、`accept-local.cmd`。验收范围以 `data/acceptance/local_demo_v1.json` 为准；面试可以打开每次独立输出的report.txt、分类支持矩阵与六行订单来源记录，说明实际通过的项目和保留的限制。

本轮[统一验收证据](evidence/local-acceptance-20261126.json)记录1051项测试通过、1项已知V1预期失败及1项弃用提示，五段验收全部通过。当前模拟库24个商品记录、31笔模拟订单是持续演练累积，不是真实GMV或真实客户规模；新增测试商品已下架，原7件在售商品保留。

## 面试演示

1. 展示一条评论主题的原文证据，解释为什么评论痛点不能等同于市场需求。
2. 缺少物流成本或风险未核查时保存待补充决策；完整演示参数产生 GO，保留两个版本。
3. 上架两件商品，用虚构买家加入购物车并合并结算。解释任一 SKU 不足时整单回滚。
4. 展示订单快照、模拟支付事件与库存流水，说明为什么回调重复不会重复扣库存。
5. 发货时增加记录物流费，查看预测差异；买家申请退款，卖家审核后登记损失，贡献利润转为负值。
6. 说明 SQLite 单体的适用范围、未实现的部分退款和真实外部接入，以及未来迁移 PostgreSQL 的触发条件。

## 可讨论的取舍

- 单件选品按每件预测，新订单已采用按笔支付费与整数分摊，旧订单保留历史口径。费用仍是演示假设，未接入服务商账单。
- 决策中的风险 clear 是演示确认，未建立法律合规知识库。
- 模拟支付由卖家触发，未实现真实网关签名、对账或退款接口；这些不应写成已接入。
- 买家邮箱目前不验证，不提供密码找回；本地演示与公网账户体系有明确距离。
- 退款净损失采用显式记录，而非虚构精确的会计利润。
