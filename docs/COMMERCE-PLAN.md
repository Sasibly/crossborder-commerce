## 复核结论

原规划方向成立，但不应将未经核验的参数、模拟销售、或 Amazon/FBA 的结论直接包装为独立站经营判断。

1. 市场（US）与渠道（AMAZON_FBA / INDEPENDENT_STORE）分开。旧 `/v1/decision` 保持 Amazon/FBA 口径；新 commerce 决策只接受独立站渠道。不共用最终结论。
2. 独立站需要获客成本假设。首版明确卖家承担运费、不代收税费；不是实时税务或合规判断。风险 clear 是卖家的演示确认，不代表法律核验。
3. GO 只表示输入完整、风险标识 clear、预计单位贡献利润大于零，不代表有市场需求或值得商业投入。规则版本为 store-demo-v1。
4. 预测、商品、订单各自保留快照。每个决策可生成一个商品草稿，重复请求返回原草稿；每次重新评估生成独立版本。
5. 第一版收敛为单商品立即购买、单商家、US、USD、模拟支付/发货。购物车、多商品订单、账户登录及买家主动退款申请后续再加。
6. 首版复盘按订单展示，并只对 completed 订单比较。采购、手续费、获客及售后仍为假设，只有物流费来自模拟发货填写。退款单不输出利润，待完整损失模型后纳入。
7. 数据回流展示预测偏差，不自动训练、修改评分或声称验证选品效果。

## 实际架构

保留原有 Python/FastAPI/SQLite 单体应用，新增 commerce 业务模块和 HTTP adapter。旧选品入口 `/`、`/console` 与 API 保留；`/workbench` 是卖家工作台，`/shop` 是英文演示商城。

评论桥接通过原 analyze_reviews 管道，强制使用 mock 规则抽取与 hash 聚类，不消耗在线模型费用。候选商品保存服务端重算并验证的主题证据，而不是接受客户端伪造的证据。现阶段桥接样本数据；live job 结果关联属于后续事项。

数据表在新增迁移 0018 中建立，支持 up/down/up 校验：候选、决策、商品、订单、支付事件和库存/操作流水。

SQLite BEGIN IMMEDIATE 串行化写事务；条件更新保证不超卖。下单预留库存，取消释放，支付扣减预留；未发货退款回库，已发货退款不自动回库。支付与超时先后争抢同一事务锁，终态不能被迟到支付覆盖。订单 15 分钟超时，下一次下单或卖家手动操作触发清理，无后台自动定时器。

## 当前范围的限制

这是本地可运行原型，尚不是公开生产站。默认只绑定 127.0.0.1；卖家复用原 API Key 鉴权，未实现员工角色或买家账户。买家使用随机订单访问凭证，不能看到成本和决策数据。公开商城固定 SHOP_TENANT（默认 local），卖家 Key 的租户必须与其一致。

支付成功、发货、完成和退款都由卖家工作台模拟触发，不是真实网关 webhook；买家不能自己标记支付成功。不存收件人地址、银行卡等资料。真实公开部署前需补账户、访问控制、反滥用、合规审查与服务商接入。

已配置 GitHub Actions 测试工作流，但尚未推送或执行远端 CI。第二版已实测 Docker 构建、容器冷启动/重建和宿主机及容器内备份恢复；未声称生产灾备或特定 QPS。没有为了原型加入 Redis、微服务或消息队列。
