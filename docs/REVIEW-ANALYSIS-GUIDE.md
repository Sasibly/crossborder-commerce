## 离线分析与文件导入

选择“离线规则，不调用外部模型”，可以分析六个内置品类前10条模拟评论，也可以导入最多10条评论。

导入步骤：选择JSONL或CSV文件 → 点击“校验导入评论” → 确认来源为已校验导入评论 → 选择对应品类 → 点击“获取评论分析结果”。文件最大65KB；每条正文1—4000字符，评分1—5，评论ID唯一。支持字段为 `review_id`、`asin`、`rating`、`title`、`body`、可选 `lang`；title可省略或留空。额外字段需在导入前移除或映射。

JSONL示例（一行一条记录）：

```json
{"review_id":"demo-001","asin":"DEMO-PET-001","rating":2,"title":"Noisy pump","body":"The pump is loud.","lang":"en"}
```

CSV示例：

```csv
review_id,asin,rating,title,body,lang
demo-001,DEMO-PET-001,2,Noisy pump,The pump is loud.,en
```

导入数据标为 `user_provided_unverified`，不自动标成真实市场数据。当前用户授权只允许将内置宠物饮水机模拟评论发送到百炼，因此导入数据目前仅能离线分析。页面切换到真实模式时会锁定宠物饮水机和内置模拟评论，服务端也会拒绝其他品类和导入评论的真实调用。

## 授权与故障处理

- 初次授权绑定同一批宠物饮水机模拟评论，最多10条；总计最多20次HTTP请求尝试，包括网络重试、格式修复和JSON模式兼容重试。
- 在每次请求之前，先在数据库事务中占用次数。网络失败也保守计入上限；用量不会因为重启、重复提交或换幂等键而归零。
- 页面有独立的排队、运行、成功、部分成功与失败状态。失败评论不参与有效主题聚合，逐条结果仍保留。
- 正在运行的任务若被进程中断，重启后标记失败，不自动重复可能计费的请求。已成功结果保留；需要重试时先核对剩余额度。
- 401/403等身份错误会停止该任务后续网络调用；不会悄悄降级成规则结果冒充模型结果。
- 请求失败可能仍有计费；页面Token仅统计已成功取得响应所报告的用量，不作为账单金额。实际费用以百炼账单为准。
- 受保护配置中，仅owner可发起真实模型调用；operator可以提交离线分析，viewer只读。本机默认owner仍保持演示配置。

首次联调当时使用10次真实请求。性能排查时发现已有第二次成功任务，累计已使用20次；本次优化读取已有记录、使用模拟传输器和缓存完成验证，额外真实请求为0。扩大数据范围、切换模型或提高上限需要新的明确授权和相应配置实现，不提供网页清空预算按钮。

## 2026年11月25日性能问题与优化验证

### 原因

数据库中两份真实成功任务的管道耗时分别为12772和13318毫秒，每份均发出10次请求。旧代码把抽取并发数固定为1，10条评论逐条等待外部模型返回，等待时间累计。这是已确认的主要结构性瓶颈。原任务没有逐请求和阶段计时，因此无法从历史记录精确划分模型推理、网络和数据库各占多少，也不能仅凭总耗时认定百炼服务异常。

两次任务均为10条、10次请求，不存在额外重试放大；思考模式原先已关闭，不是本次新增优化。旧页面每1.5秒刷新配置、任务列表和完整详情，增加完成后的显示等待与重复传输；更换提交幂等键还会重复分析同样的输入。

### 修改后的行为

- 单批最多3条并发，仍然逐条抽取、校验证据并按输入顺序保存结果。没有合并成一次多评论提示词，也没有改变单条输出、授权范围或20次硬上限。每次请求仍先通过数据库事务占用额度，包含重试和格式修复。
- 同租户、同输入、同模式且来源与模型/提示词/标签/聚类版本一致的完整成功结果默认复用。部分成功、失败、其他租户或版本不匹配的结果不会命中。显式重新分析和幂等重放有独立语义，旧记录不覆盖。
- 每条结束后保存已完成数、通过数和总数；前端前5秒每500毫秒读取轻量进度，随后每1.5秒读取，任务结束再取完整结果。进度接口执行租户权限校验，切换任务后不会被旧轮询覆盖。较慢的轮询阶段也避免持续每秒多次读取触及受保护模式限流。
- 新任务报告保存 `timings`、`request_attempts`、`execution` 和 `progress`。可区分抽取墙钟时间、聚合、进度落库、额度占用与请求尝试。并发请求耗时之和存在重叠，不能与墙钟时间相加；请求尝试计时包含相关重试退避，不应当解释成纯服务端推理时间。历史终态记录不补写统计。
- 工作线程无排队任务时先只读检查，避免空闲轮询反复取得SQLite写事务。

## 宠物饮水机标注规范与待审草稿

已新增本机标注准备和检查工具 `scripts/review_annotation.py`，用于把标签缺口转化为可审核的标注草案。目录 `data/review-annotation/pet_fountain_schema_v1.json` 定义24个拟议标签，当前版本为 `pet-annotation-2ecd8768ed73b0a7`，阶段固定为 `annotation_draft_not_production_taxonomy`。**它不是线上10标签的新版本，也没有扩大模型提示词、改变V2提取规则或重算旧版成绩。**

### 标注边界

| 范围 | 代表维度 | 必须区分的事实 |
|---|---|---|
| product | 水泵耐用性、出水、漏水、声音、清洁、拆装、污垢、控制、容量、电源线、外观、宠物意愿、饮水行为、过滤感知、整体运行感知、潜在安全担忧 | 出水弱不等于寿命失效；易脏不等于难洗；装配不便不等于清洗困难；容量不等于外形尺寸 |
| consumable | 滤芯更换频率、滤芯成本、更换提醒 | 提醒不亮不证明滤芯失效；未指明对象的“贵”不能归为滤芯成本 |
| service | 客服、退换流程、说明书 | 服务响应慢不等于产品出水慢；服务体验不能混作产品故障 |
| experience | 整体使用、价格感知 | 单个白天声音场景不能扩大为整体评价；价格抱怨不直接指定部件 |
| assertion限定 | observed / reported / corrected / uncertain / potential_risk | 转述不是本人确认；纠正归因不当作原故障事实；不确定归因可单独作为context记录；潜在风险不能当作已发生事故 |

宠物愿不愿意喝与喝水多少分开；水清澈只是用户感知，不证明化学或微生物安全；饮水增加不证明健康收益。潜在安全担忧标签只能使用 `potential_risk`。完整的每个标签“包含/排除”边界随工具输出在 `label-catalog.json` 和中文 `annotation-guide.txt` 中。

### 本地操作

```powershell
# 从原10条演示评论和20条固定反例生成独立草案，不修改源文件：
.\.venv\Scripts\python.exe scripts\review_annotation.py
# 编辑/复核后检查一份草案，另存报告：
.\.venv\Scripts\python.exe scripts\review_annotation.py --lint 完整路径\annotations-draft.json
# 从未来提供的未核验评论原文准备草案：
.\.venv\Scripts\python.exe scripts\review_annotation.py --prepare-reviews 完整路径\new-reviews-template.json
```

每次输出到 `reports/review-annotation/时间戳-随机后缀/`，包含：

- `annotations-draft.json`：逐条原文、原标注、来源快照及拟议标签、情绪、限定、证据位置、复核状态。
- `validation-report.json`、`review-queue.json`：结构错误、语义边界提示、重复维度、待审项和当前审批内容指纹。
- `label-catalog.json`、`annotation-document.schema.json`：标签边界及结构契约，便于外部编辑器校验。
- `annotation-guide.txt`：中文填写/复核规则。
- `new-reviews-template.json`：未来输入模板，初始reviews为空；填写至少一条原文后再使用 `--prepare-reviews`。

模板外层字段为category=pet_fountain、data_kind=user_provided_unverified、source_metadata和reviews。source_metadata可填写platform、product_reference、market、review_period、rights_note；它们是来源声明，不是本工具核查通过的证明，也不授予模型传输权限。reviews每条填写review_id、body、rating；没有评分必须写null，不从情绪推断。工具只做本地整理，不访问source_reference中的地址，也不调用模型或打开业务数据库。

### 复核与完整性约束

原source_snapshot及original_annotation保留，与拟议标签分开；源内容、评分、ID或原标注被改写，检查会报错。原始文件哈希在准备时记录，通用lint不会自动打开原文件或远程链接；这些哈希用于发现意外漂移，不是来源真实性或人工身份签名。

证据使用原文非空片段，并保存start/end，按Python Unicode字符索引计数，end为不含末尾的区间边界。位置、长度和原文包含关系均校验；此项只证明引用位置，不证明标签语义正确。

拟议状态为draft或needs_review；人工作出approved/rejected决定时，必须填写approval：reviewer_id、reviewer_kind=human、带时区reviewed_at、rationale、payload_hash。先检查/修改拟议内容，再运行lint取得review-queue中的current_payload_hash，最后记录决定。内容、证据、范围说明、来源或目录版本变更后，旧审批指纹失效。相同维度存在相反情绪时须提供scope_note区分场景，避免无语境地批准矛盾标注。人工身份及决定是输入声明，未被独立认证。

此工具不会自动批准、导出金标准或产生Precision/Recall/F1。即使输入声明全部人工复核，它也不自动升级为真实质量证据；合成数据始终保留合成来源。将来若要真正启用新标签，需要独立标注裁定和新的评测版本，不能把变化后的定义与旧9单元/6单元的F1直接比较。
