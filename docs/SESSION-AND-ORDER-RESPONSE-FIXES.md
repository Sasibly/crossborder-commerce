# 审查优先项修复（2026-11-26）

本轮按用户确认处理审查清单中的1、2、4项：身份切换竞态、买家按钮进行中状态、卖家订单写响应脱敏。当前目录仍不是Git仓库，修改前git diff/status无法生成差异，未初始化Git。

## 实现

- 买家共享API和私有数据加载使用身份代次及买家ID检查。登录、退出、会话失效时清空订单、地址、购物车、结算幂等上下文及私有表单；旧响应、旧401、A→B→A的旧请求都不能写回新账户。刷新去重状态按Promise实例清理，避免旧请求清掉新身份的刷新任务。
- 卖家共享API绑定Key和身份代次；改Key清空旧店铺商品、候选、订单、角色、汇总、审计、售后、供应商、场景和评论任务/导入状态，并停止旧轮询。跨多个await的管理加载、候选交接和文件导入增加上下文检查，防止旧角色在后续审计返回后重新生效。旧响应被丢弃，不改变已提交到服务端操作的事务语义。
- 买家以稳定操作标识维护进行中状态。结账与鉴权状态共同参与按钮禁用；同一订单的付款/取消/退款共享操作锁，购物车操作共享锁。刷新替换DOM后仍能恢复锁定；旧身份操作结束不能释放新身份同名操作。无关操作结束不会提前启用结账。
- 卖家pay、ship、complete、refund、cancel统一通过seller_order投影返回，移除完整地址、token、request_key、fingerprint；返回Cache-Control: no-store。保留成交商品、金额和状态，完整地址继续由同店铺owner/operator单独读取。领域层及数据库历史快照不改写，买家自己的地址读取边界不变。
