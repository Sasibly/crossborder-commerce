## 关键边界

- 原订单、报价、决策及商品快照不被改写。商品替换生成新SKU，不把历史订单价格替换为新价格。库存转移写入正负流水，失败整笔回滚；有待支付预留、不同候选、非GO、已使用的新版本均拒绝替换。
- 下架状态沿用现有 `draft`，可以再次入库和上架。它停止新购买，已有订单继续处理。旧版已支付订单后续退款所恢复的库存归旧SKU，处于下架状态时不会自动进入新版本可售库存；避免无依据合并库存。
- 已拒绝申请不会因后来主动退款而改写成“审核同意”。最终执行状态取订单事实。升级前无独立执行事件的退款不补造执行时间。
- 新商城使用 `GET /shop/api/checkout-preview` 后提交 `cart_fingerprint`。旧账户结算客户端暂可省略该字段，但购物车非空时重放已用旧键会返回409。服务端保留原意图重放能力，前端针对变化后的预览生成新键，不能每次网络失败都盲目换键。
- 创建候选的HTTP客户端须先取当前 `/v1/commerce/evidence/{dataset}` 返回的 `evidence_fingerprint`；构造主题编号已不足以创建候选。旧离线演示脚本已同步。
- `COMMERCE_LEGACY_GUEST_CHECKOUT=true` 只供显式兼容测试和独立临时库演示；当前8031默认关闭。旧游客订单的token读取保留，不破坏历史查询。兼容写入口不提供完整账户和地址闭环，不应作为日常商城入口。
- 8031是本轮统一日常入口；8027开发进程此前已停止，本轮没有为验证而重新启动。端口隔离通过临时实例测试验证，不宣称8027正在运行。

## 重复验收与日常使用

```powershell
cd D:/Codex_Projects/crossborder-commerce
.\local-commerce.cmd verify
.\.venv\Scripts\python.exe scripts/commerce_consistency_smoke.py --report-dir reports/local
```

第一条验收命令会创建模拟交易并短暂重启容器。第二条会创建虚构买家、候选、订单和测试商品，最终下架其商品、保留业务历史；应按需要执行，不用于无副作用的健康探针。

日常刷新8031工作台和商城即可使用修复。改价先保存同候选的新GO决策，再从旧商品执行“替换上架版本”；仅希望停止售卖时使用“下架”。所有供应商、支付、发货和退款继续模拟，真实统计来源与模拟经营数据保持独立。
