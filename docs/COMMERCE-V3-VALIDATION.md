# 第三版验收记录

日期：2026-11-24（Asia/Shanghai）。本轮范围：卖家角色、成功业务变更审计及经营汇总。

## 权限检查

新增 owner/operator/viewer。由 API Key 派生角色，客户端请求体不能指定自身权限。viewer 所有受 Key 保护的写请求返回 403，包括旧 `/v1/jobs`；operator 可以入库、发货，但不能模拟支付成功、主动退款、审核售后或登记退款损失。跨租户数据继续隔离。

旧 Key 默认 owner 是兼容现有权限的显式选择，不代表历史 Key 已实施最小权限。Key CLI 新增 `--role`，没有新增网页授予角色功能。关闭 AUTH_REQUIRED 的本地演示仍使用 owner，不能用该模式证明公网访问控制。

## 审计检查

新增 `commerce_audit`，业务服务在同一事务中写事件，HTTP 请求通过相同连接上下文绑定卖家或买家身份；后台任务与脚本记作 system。读取接口不生成业务事件，幂等支付及幂等草稿不重复生成业务效果事件。

测试注入审计 INSERT 失败，确认库存及流水事务回滚。UPDATE、DELETE 被触发器拒绝。API 按 tenant 查询、支持 after/limit 游标，不暴露内部 actor_id 哈希或输入正文。

审计不是 HTTP 全量访问日志，拒绝/失败请求由原结构化日志记录；也不是防御数据库管理员篡改的外部不可变存储。

## 经营汇总检查

`GET /v1/commerce/summary` 返回各状态单量、累计模拟收款、整单退款、退款后留存收款、已知贡献、完整贡献及缺失成本单量。

用一笔未登记损失的已退款单验证：收款 3000 分、退款 3000 分、留存 0；已知贡献小计 0，但完整贡献为 null、缺失成本 1 单。不同租户统计为空。贡献只包括完成和退款单，不将待支付、取消、在途订单虚构为已实现利润。
