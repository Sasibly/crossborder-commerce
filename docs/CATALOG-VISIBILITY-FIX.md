# 分析品类与商城商品展示修复

验收日期：2026-11-25，Asia/Shanghai。范围：本机部署与验证。

## 原因

用户截图一来自 `/console` 的 Amazon/FBA 分析表单，六个选项是用于数据集和规则匹配的分析品类，并不是六个已创建、已上架商品。商城 `/shop` 只读取当前店铺已上架的 SKU；原初始化脚本实际仅创建两个宠物饮水机商品，因此原显示与数据库一致。原界面将表单称为“商品”，且缺少上架状态说明，造成误解。

## 已完成

- 分析页明确标注“分析品类（用于规则匹配，不是已上架商品清单）”，说明与独立站的关系，链接携带当前品类前往工作台。
- 工作台显示每个品类的候选 SKU、草稿、已上架 SKU 和有货 SKU 数量，可以选择该品类继续分析和操作。创建候选后自动选中新候选。分类统计按当前身份的租户隔离。
- 买家接口从商品原有不可变候选快照提取受控品类信息，仅增加公开品类 ID 和名称；不暴露采购成本、供应商或完整决策。商城提供品类筛选及商品数量。
- 幂等种子脚本补齐空气净化器、半自动咖啡机、电热水壶、扫地机器人、无线充电器各一个演示 SKU，保留原两个宠物饮水机。所有新演示商品通过正常候选、GO 决策、草稿、入库和上架流程创建。
- 六种分析选项不会自动转为商品；有库存的草稿也不会提前展示。未知品类归入“其他”，不会凭外部字符串扩展分析规则清单。

演示价格、采购成本、物流、售后、获客和风险已检查标记全部为虚构流程输入，来源在种子脚本及决策 source_note 中明确记录，不代表真实行情或真实合规认证。供应商及交易继续模拟，没有接入真实供应商；没有新增或改变公开行业指标。
