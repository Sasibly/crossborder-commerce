# CrossBorder 本机使用说明

适用版本：2026年11月26日本机收尾版本，8031、schema26。

卖家工作台现按业务分区显示，默认打开“经营概览”，左侧导航切换模块；手机使用顶部常驻的“业务导航”折叠菜单。切换模块保留当前表单内容，地址中的 `#模块/区域` 支持刷新、收藏及前进后退。完整分组见[工作台结构说明](SELLER-WORKSPACE-IA.md)。

| 想做什么 | 导航入口 |
|---|---|
| 看经营汇总与品类上架进度 | 经营概览；首页还有订单、商品、售后、评论四个快捷入口 |
| 入库、上架、下架、生成草稿或替换商品版本 | 商品与库存 → 商城商品与库存 / 决策与商品准备 |
| 查询和处理订单、审核买家退款 | 订单与售后 → 订单查询与履约 / 买家售后申请 |
| 分析或导入评论、查看已保存任务、创建候选 | 评论分析 → 评论分析任务 / 快速离线机会 |
| 填成本、模拟询价、比较报价、保存场景测算 | 选品与成本；先在工作区顶部确认“当前候选商品” |
| 比较预测和经营结果 | 经营复盘 |
| 核对公开统计及模拟假设 | 指标来源 |
| 填卖家 Key、设置支付费、检查一致性、查看审计 | 设置与审计 |

“商品与库存”可按名称 / SKU / 品类关键词、状态和品类组合筛选；清空关键词、选择全部状态和全部品类可恢复完整列表。筛选只影响当前显示，切换模块会保留条件，不会改变上架状态或库存。

订单区已升级为摘要列表与按需展开详情：进入“订单与售后”→“订单查询与履约”。列表包含创建时间、成交商品/SKU/数量、总额与币种、脱敏收件地区、状态及待处理提醒；点击“查看订单详情”查看商品明细、金额、支付/模拟物流、售后和时间线。详见[订单信息与权限说明](SELLER-ORDER-DETAILS.md)。

本轮五段统一验收已全部通过，结果见[验收摘要](evidence/local-acceptance-20261126.json)。日常运行成功时打开其输出目录的report.txt；1051项测试通过之外，报告还明确记录已知预期失败、各品类分析限制和实际交易/恢复证据，不仅是测试数量。

首次使用先执行 `.\local-commerce.cmd deploy`，日常完整检查执行 `.\accept-local.cmd`。统一验收会运行测试和离线评测，并在本机创建虚构商品、买家、六行订单，模拟支付/发货/退款后下架测试商品，再做备份恢复和重启；新记录保留，原商品和历史不重置。运行期间请暂停手动操作，结果位于 `reports/local-acceptance/` 各独立目录。

本版六品类都可演示交易流程，评论分析效果有明确范围：宠物饮水机V2，其他五类仍为有限质量V1，不代表各类分析均准确。线上仍使用10标签，24标签和AI预审参考是本机标注草案。评论与标注采用用户提供的合成演示数据完成本轮验收，报告保持合成来源，不要求补充真实数据。

下面的评论分析/标注命令为进阶工具；日常浏览器操作从第1节开始，架构和五分钟演示见[演示说明](COMMERCE-DEMO.md)。

独立百炼评论分析位于左侧“评论分析”→“评论分析任务”。真实调用已完成10条模拟评论联调；查看结果、导入和授权限制见[百炼评论分析说明](REVIEW-ANALYSIS-GUIDE.md)。本文第3节的“快速离线机会”入口仍为离线规则；真实模型只在任务区显式发起。

分析区按钮现为“获取评论分析结果”：默认复用同输入、同版本的成功结果，命中时不会新增模型请求；新分析最多3条并发并显示进度。只有勾选“重新分析，不复用已有结果”才强制重算。11月26日追加测速完成，两轮约6.1秒和6.2秒；原授权与追加授权均已使用20/20，累计40次，可继续查看和复用结果。

新增独立本机演示评测命令：`.\.venv\Scripts\python.exe scripts\review_demo_eval.py`。它分析用户确认的10条宠物饮水机合成评论，输出到 `reports/review-demo-eval/` 的独立目录，打开中文 `report.txt` 即可查看每条评论的映射和差异；`report.json` 提供完整结构。该工具使用离线规则，不是网页里的百炼调用，局部计分也不代表真实准确率。

新上传的20条合成反例另用 `.\.venv\Scripts\python.exe scripts\review_holdout_eval.py`，输出到 `reports/review-holdout-eval/`。因文件没有评分，主报告明确假设3星，并附1星、5星敏感性结果；这些星级不是实际评论评分。它保留原整体情绪但只评价可对齐的方面标签，不消耗模型额度，也不会放宽网页输入限制。

宠物饮水机的工作台离线分析现已使用V2：刷新工作台、选择离线规则后点击“获取评论分析结果”即可；原V1缓存会按版本区分，新计算不消耗模型额度，旧任务仍可在历史中查看。其他品类继续使用V1。命令行单集评测需要加 `--rules v2` 才选择新版；默认V1用于复现原基线。完整对照可运行 `scripts\compare_offline_rules.py`，打开输出目录中的中文 `comparison.txt`。

如需整理标注，运行 `.\.venv\Scripts\python.exe scripts\review_annotation.py`，打开输出目录中的 `annotation-guide.txt`、`annotations-draft.json` 和 `review-queue.json`。工具会保留全部原标注并给出拟议分类；编辑后用 `--lint 文件完整路径` 复查。6个重点边界项和其余49项均须人工复核，工具不会自动批准。`new-reviews-template.json` 可用于以后填写未核验评论原文，缺失评分写null；仅本地准备不授予发送到百炼的权限。

本轮工作副本建议使用 `.\.venv\Scripts\python.exe scripts\review_annotation_prereview.py` 生成。打开 `prereview-report.txt` 看55项AI建议，`annotations-prereviewed.json` 是应用建议后的独立副本，`change-audit.json` 保留前后差异。`pending-human-items.json` 单列两处原文不足的问题；全部标注都尚未人审批准。检查新副本可继续运行 `scripts\review_annotation.py --lint 新副本完整路径`，但不要将修改后的副本重套旧AI计划。AI参考候选仅用于本地标注开发，不能当作真实金标准或模型成绩。

本系统将评论分析、选品决策、商品上架、买家下单、卖家履约和经营复盘连接起来。可以在同一台电脑分别打开卖家工作台与买家商城，完成一次模拟交易。

供应商、报价、样品、支付和物流全部为本地模拟，不发送真实询价，不收取真实资金，也不会实际发货。请使用虚构地址和未在其他地方使用的测试密码。公开行业指标有独立来源说明，不代表本项目的真实经营结果。

本次说明核对时，8031健康接口返回 `ok/mock`，商城有六个品类、七件已上架演示商品。商品数量会随之后的操作变化。

### 1.2 服务打不开时

打开Docker Desktop，等待其启动。在PowerShell执行：

```powershell
cd D:/Codex_Projects/crossborder-commerce
.\local-commerce.cmd start --skip-build
.\local-commerce.cmd status
```

`start --skip-build` 使用本机已有镜像，保留原数据库，并幂等补齐演示数据。看到 `state: running`、`health: healthy` 后，再打开上面的地址。

源码修改后需要重新构建，可以执行：

```powershell
.\local-commerce.cmd start
```

若需要一次完成构建、启动、演示数据准备和自动验收，执行 `local-commerce.cmd deploy`。它会创建模拟测试订单并进行一次受控重启，适合部署验收，不必每次打开页面都执行。

以上命令依赖项目现有的 `.venv` 和已安装的Docker。当前机器已经具备；迁移到另一台机器时，先按[项目说明](../COMMERCE-README.md)准备依赖。

## 2. 理解品类、候选和商城商品

```text
选择分析品类 → 查看评论主题 → 创建候选SKU → 保存独立站决策
                                      ↓ GO通过
                              新建商品草稿 → 入库 → 上架
                                                        ↓
                                                  买家商城可见
```

- **分析品类**：决定使用哪份评论数据和规则，不是商品记录。当前包括空气净化器、半自动咖啡机、电热水壶、宠物饮水机、扫地机器人和无线充电器。
- **候选SKU**：待评估的商品想法，保留选中的评论主题和证据。
- **决策版本**：保存当时的成本、风险和来源。重新评估会新增版本。
- **商品草稿**：由通过的决策生成，尚未对买家展示。
- **已上架商品**：商城展示的实际SKU。已经售罄的商品也可保留展示，但不能加购。

卖家的全部商品记录可以多于商城商品。工作台包含草稿、已下架记录和验收记录；商城只展示已上架商品。`draft` 在当前版本中同时用于未上架草稿和已下架商品。

已有七件演示商品分别是：宠物饮水机两件，其余五个品类各一件。此前一致性验收还保留了四条 `SIM / Consistency verification` 下架商品，用于保留订单和库存审计；它们不会出现在商城中。

## 3. 卖家创建并上架商品

### 3.1 从评论建立候选

1. 打开工作台，进入“评论分析”→“快速离线机会”，选择“评论数据集”。也可使用“评论分析任务”中已保存的机会主题建立候选。
2. 等待主题加载；需要重新分析时点击“分析评论机会”。加载期间不能创建候选。
3. 在“机会主题”选择痛点，查看下方原文证据。
4. 填写可辨认的名称，例如 `SIM / 易清洁饮水机 A`。
5. 点击“创建候选 SKU”。创建成功后，自动跳到“选品与成本”→“成本与风险”，顶部已选中新候选。

切换品类会重新加载主题。评论来自离线构造样本，不能据此声称已经证明真实需求。“经营概览”→“品类上架进度”中的“查看该品类”也可选择相应数据集和已有候选，并进入快速离线机会。

### 3.2 填写成本与风险

先进入“选品与成本”，确认顶部“当前候选商品”的名称，再在“成本与风险”填写参数。本区的供应商模拟、报价比较和场景测算共享这个候选选择器。金额输入框以“分”为单位，人民币采购与美元费用不能混用。保存新决策后，自动进入“商品与库存”→“决策与商品准备”。

下面是一组用于练习的虚构输入，可以在不引用报价、比较或售后场景时使用：

| 输入项 | 填写值 | 含义 |
|---|---:|---|
| 售价 USD 分 | 3000 | 售价$30.00 |
| 采购成本 CNY 分 | 7000 | 采购¥70.00 |
| 汇率 CNY / USD | 7 | 1美元兑换7元人民币的模拟假设 |
| 每件物流 USD 分 | 500 | 每件$5.00 |
| 支付费率 基点 | 300 | 3% |
| 每件固定支付费 USD 分 | 30 | 单件预测按$0.30计算 |
| 预计售后 USD 分 | 100 | 每件$1.00的模拟假设 |
| 预计获客 USD 分 | 300 | 每件$3.00的模拟假设 |
| 风险检查 | 演示案例：已检查 | 仅为演示确认，不代表真实合规认证 |
| 参数来源与假设 | 本地练习参数，全部模拟，未核验真实报价和需求。 | 说明适用范围 |

点击“保存一次新决策”，在“决策与商品准备”查看结果：

| 结果 | 含义与下一步 |
|---|---|
| `GO` | 当前输入完整、风险标记通过且预测每件贡献利润为正；允许生成草稿 |
| `NEED_MORE_INFO` | 有缺项或风险仍待核查；补全后保存新版本 |
| `NO_GO` | 风险阻断或预测贡献利润不为正；调整方案后保存新版本 |

上面的独立算例预测每件贡献利润为$9.80。若后来采用售后场景、模拟报价或比较情景，结果应按实际采用的参数重新解释。

风险、来源和成本不会因为切换候选而自动变成该商品的真实数据。保存前逐项确认；输入未知费用时留空表示未知，不要为了得到GO而填写无依据的零。

### 3.3 草稿、入库与上架

1. 找到目标候选对应的GO决策，核对决策ID与成本快照。
2. 点击“新建独立 SKU 草稿”。同一决策重复点击不会复制商品。
3. 在“商城商品”找到该SKU，填写入库数量，例如10，点击“确认入库”。
4. 点击“上架”。库存必须大于零。
5. 到买家商城点击 **Refresh products & cart**，确认商品出现、品类和售价正确。

入库表示向当前SKU增加模拟库存。重复点击“确认入库”会再次增加库存；它不是保存按钮。该操作不代表真实采购、收货或仓库验收。

## 4. 使用模拟报价与业务指标

这些功能用于解释决策来源，熟悉基本上架流程后再使用。

### 4.1 模拟供应商流程

1. 先选中目标候选SKU。
2. 在“供应商模拟工作流”选择常规或延期场景，点击“创建模拟询价”。
3. 按页面当前允许的按钮依次操作，例如“模拟发出询价”→“模拟供应商返回报价”。
4. 需要演示样品时，继续“模拟申请样品”→“模拟收到样品”；再接受或拒绝方案。
5. 返回成本区，在“模拟报价引用”选择该候选的可用报价，并将采购成本填写为报价金额。

常规场景为¥70/件、MOQ100、14天；延期场景为¥90/件、MOQ200、30天。全部为本地固定模拟值。接收样品或接受方案不会自动入库、付款或上架。

### 4.2 退货指标与场景测算

在“业务指标来源”展开指标，查看市场、期间、渠道、统计口径、适用范围和原始来源。然后在“候选商品场景测算”选择指标，按页面提示输入金额、填写假设并保存。

- 公开销售额退货占比用于销售额参照，不能直接当作某SKU的单件退货概率。
- 单独标注的模拟单件概率，可以计算演示用的期望售后损失。例如假设概率10%、每次损失2000美分，期望损失是200美分；两项输入均为模拟假设。
- 可用的模拟售后场景需要点击“采用场景售后成本”才会填入成本表单；保存场景本身不会自动修改决策。

### 4.3 比较两份报价与利润压力

1. 为同一候选准备两份已返回报价的模拟流程。
2. 补全上方成本表单，选择报价A、B。
3. 在“模拟报价与利润压力比较”填写压力售价、汇率、物流和适用范围，点击“保存报价与压力比较”。
4. 查看基线、售价下降、汇率不利、物流上涨和综合压力五种情景。
5. 选择目标情景的“采用此情景”，核对成本表单，再点击“保存一次新决策”。

压力售价与CNY/USD不得高于基线，压力物流不得低于基线。采用情景不会直接下单或上架。如果引用后又手改相关成本，保存时可能被拒绝；需要重新采用，或通过“清除比较引用”后说明新的手工假设。

## 5. 买家浏览、登录与下单

商城为英文界面，主要按钮对应如下：

| 界面文字 | 用途 |
|---|---|
| Sign in / Sign out | 登录 / 退出 |
| Browse category | 按品类筛选 |
| Add to cart | 将所选数量加入购物车 |
| Update quantity / Remove | 保存购物车数量 / 移除商品 |
| Refresh products & cart | 刷新商品及购物车 |
| Place demo order | 创建模拟订单 |
| Refresh orders | 刷新订单，并同步刷新商品及购物车 |

### 5.1 地址与购物车

1. 使用演示账号登录。
2. 展开 **Add a US demo address**，保存虚构美国地址，例如：

| 字段 | 虚构示例 |
|---|---|
| Recipient | Demo Buyer |
| Address line 1 | 123 Example Street |
| Address line 2 | 留空 |
| City | Seattle |
| State | WA |
| ZIP code | 98101 |

3. 选择已保存地址。
4. 在商品卡片填写数量并点击 **Add to cart**；重复加购会累加数量。
5. 在购物车修改数量后点击 **Update quantity**；点击 **Remove** 移除。

每种商品数量最多20，每个购物车最多20种商品；同时受可售库存限制。购物车不预留库存，另一买家可能先购买。下架或库存不足的购物车商品需要移除、调整或等待补货。

### 5.2 下单

确认地址、商品和数量后点击 **Place demo order**。服务端按当前商品数据计算金额，成功后清空购物车，订单显示 `pending`，并预留库存15分钟。

当前演示售价包含卖家承担的物流，演示不代收税费；页面金额不是用于真实交易的税务或运费报价。结算不会收取资金，下单后在买家商城 Your orders 中点击 Pay … (simulated) 完成模拟付款；不收取真实资金。

空购物车、商品下架或数量超过库存时，结算按钮禁用。收到购物车变化提示后，刷新并重新确认。网络异常时先点击 **Refresh orders** 检查订单是否已经生成，再决定重试，避免把新购物当成旧订单的重试。

## 6. 卖家处理订单

1. 回到工作台“订单与履约”，点击“刷新订单”。使用完整订单ID核对目标订单。
2. `pending` 订单等待买家在商城 Your orders 点击 **Pay … (simulated)**。金额由服务端读取原订单，不能在页面改写；卖家不代买家付款。
3. 对 `paid` 订单填写虚构物流单号和本单实际物流费，点击“模拟发货”。例如 `SIM-DEMO-001`、550美分。
4. 对 `shipped` 订单点击“标记已完成”。
5. 到买家页面点击 **Refresh orders** 查看状态和物流信息，再回卖家查看复盘。

“本单实际物流费”是整笔订单的模拟记录值，多商品订单也只填写该笔订单总物流费。

| 状态 | 含义 | 常用后续操作 |
|---|---|---|
| `pending` | 待买家模拟支付，库存已预留 | 买家付款、取消或等待超时 |
| `paid` | 模拟支付完成 | 发货或退款；退款审核中暂停发货 |
| `shipped` | 模拟发货完成 | 标记完成或退款 |
| `completed` | 模拟订单完成 | 查看复盘、申请或执行退款 |
| `cancelled` | 未支付订单已取消 | 查看历史；不可继续支付 |
| `refunded` | 已执行模拟整单退款 | 查看退款结果、登记净损失 |

买家可通过 **Cancel unpaid order** 取消待支付订单。超时订单由后台按约30秒间隔检查，释放预留库存；卖家也可点击“释放超时库存”。超过15分钟但尚未清理的订单不能再确认支付。

订单列表每页30笔，按创建时间排列，可筛选状态和创建时间；结束时间不包含在范围内。经营汇总仍为全量累计，不跟随订单列表筛选。

## 7. 退款与库存处理

### 7.1 买家申请与卖家审核

1. 买家在已支付、已发货或已完成订单下填写 **Reason for full refund**。
2. 点击 **Request full refund**。每单仅有一份整单申请，当前不支持部分退款；已拒绝申请不能重新发起。
3. 卖家刷新，在“买家售后申请”填写至少3个字符的审核说明，选择“同意模拟整单退款”或“拒绝申请”。
4. 买家刷新订单查看审核结果和最终退款执行结果。

未发货订单存在待审核退款时，不能发货。同意申请会执行整单模拟退款；拒绝后可以继续发货。卖家也可通过订单的“卖家主动整单退款”执行退款。

审核和执行是两种记录。例如申请曾被拒绝，但卖家后来主动退款，页面会同时保留“审核rejected”和“最终执行refunded”；它们分别解释历史决定和最后执行结果。

### 7.2 库存何时恢复

| 操作 | 库存处理 |
|---|---|
| 待支付订单取消或超时 | 释放预留，恢复可售库存 |
| 已支付但未发货订单退款 | 自动恢复到原SKU |
| 已发货或已完成订单退款 | 不自动恢复库存 |

已发货退款不等于货物已经退回。当前没有退货物流和质检闭环；只有在演示假设确认可再次销售后，才由卖家手工入库。旧版本订单退款恢复的库存仍属于旧SKU；旧SKU已下架时不会自动转入新商品。

### 7.3 登记退款净损失

在已退款订单展开“登记退款净损失”，填写货物、物流、不可退支付费用、其他净损失及核算依据。所有金额都是USD分。

已退回且可再次销售的货物，应在货物净损失中扣除回收价值。明确无损失才填0，未知时暂不提交。记录提交后不可覆盖；重复提交相同内容可重放，不同内容会冲突。

未登记完整损失时，经营复盘显示“待补全”。登记后按净损失的负数计入贡献，不把未知成本默认为零。

## 8. 调价、替换商品版本与下架

重新保存决策不会自动改变旧商品。按用途选择下面两种操作。

### 8.1 希望更新现有售卖方案

1. 在成本区选中原商品所属候选，修改售价或成本，填写新假设，保存新的GO决策。
2. 在旧的已上架商品下找到“替换为同候选的新决策”。
3. 选择新决策，核对ID和售价，点击“替换上架版本”。
4. 系统将旧商品的可售库存转入新SKU、下架旧商品并上架新版本。
5. 刷新商城，确认新售价；原订单继续显示原商品ID和原价。

替换要求旧商品有可售库存且无待支付预留；新版本必须为GO，且对应商品尚未入库或售卖。若有待支付订单，先处理这些订单，再替换。已创建的未入库草稿可以用于替换，不需要先手工入库。

### 8.2 希望增加独立商品或停止销售

- 新增独立商品：选择GO决策点击“新建独立 SKU 草稿”，再入库、上架。旧商品不会自动下架。
- 停止新销售：在已上架商品下点击“下架”。已有订单继续处理，原商品和库存历史保留。
- 恢复销售：在相应草稿/下架商品有库存时点击“上架”。

不要用“新建独立SKU草稿”代替调价，否则两件商品都可能继续售卖。

## 9. 查看经营复盘、权限与审计

### 9.1 经营数字如何解释

“经营汇总”展示累计模拟收款、整单退款、退款后留存、已知贡献小计、完整贡献及成本缺失数量。它按订单当前状态累计，不是按财务期间生成的报表。

“预测与经营结果”将完成订单或退款订单与原决策比较。完成订单使用记录的整单物流费，以及当时的其他成本假设；其他成本并未因此变成真实实测。

以第3节的单商品算例为例：默认订单支付假设仍是300基点加30美分，购买一件，发货物流填550美分并完成，预计显示预测$9.80、记录贡献$9.30、差额-$0.50。如果修改了成本、订单支付策略、购买数量或引用场景，不能照搬这个结果。

单件决策中的固定支付费按件预测；订单结算按当时的订单支付策略按笔计算固定费用。多件订单因此可能与“单件预测×数量”存在合理差额。“订单支付费假设”由owner修改，历史订单仍保留当时策略。

### 9.2 卖家角色

| 角色 | 操作范围 |
|---|---|
| owner | 现有全部卖家管理操作，包括退款审核、净损失及计费策略 |
| operator | 选品、商品、库存、发货和订单完成；不能执行上述资金相关操作 |
| viewer | 读取，不允许写操作 |

这些角色在开启卖家Key鉴权的配置中生效。当前本机演示关闭Key校验，因此默认owner。页面“访问设置”用于填写已有Key，不提供网页创建员工或提升权限功能。

工作台会显示当前卖家店铺和商城店铺。如果不匹配，当前卖家的商品不会出现在该商城，商城跳转也会禁用；应切换正确Key，而不是复制商品或合并数据库。

### 9.3 一致性与审计

点击“检查业务一致性”，正常结果应为 `ok: true`、`issues: []`。该功能只读，不自动修复数据。“操作审计”用于查看执行者、动作、对象和时间；订单详情中的“查看选品依据与脱敏订单快照”可追溯原决策，不包含完整收货地址或订单访问令牌。

如果检查出现异常，保留结果、订单ID、商品ID及对应时间，再查看日志。不要直接修改数据库来让数字相等。

## 10. 日常维护与验证

### 10.1 常用命令

先进入项目目录：

```powershell
cd D:/Codex_Projects/crossborder-commerce
```

| 命令 | 用途及副作用 |
|---|---|
| `.\local-commerce.cmd status` | 查看健康状态和入口，不创建交易 |
| `.\local-commerce.cmd start --skip-build` | 使用已有镜像启动；幂等准备演示数据 |
| `.\local-commerce.cmd start` | 构建并启动；已有数据保留 |
| `.\local-commerce.cmd logs` | 查看最近60行应用日志 |
| `.\local-commerce.cmd stop` | 正常停止并保留数据卷 |
| `.\local-commerce.cmd verify` | 创建模拟买家和交易，验证备份恢复，并短暂重启服务 |
| `.\local-commerce.cmd deploy` | 构建、启动、准备数据，再执行verify |

自动验收报告默认在 `reports/local/` 下，每次新建文件。`verify`需要至少两种有货的上架商品；如果自己下架或售罄了演示商品，先恢复合适的测试库存和上架状态。种子脚本不会擅自重置旧商品。

需要重放本次跨端异常路径时可执行：

```powershell
.\.venv\Scripts\python.exe scripts/commerce_consistency_smoke.py --report-dir reports/local
```

它会创建明确标注的虚构买家、候选、订单和商品，完成测试后下架其商品并保留审计历史；不是无副作用的健康检查。日常查看状态用 `status` 即可。

### 10.2 备份与恢复验证

8031工作数据库保存在Docker命名卷 `crossborder-commerce_commerce-data`，并非宿主机的 `data/commerce.sqlite3`。不要使用开发库备份来声称已备份当前Docker商城。

手工在线备份并恢复到新文件进行比较：

```powershell
docker compose exec -T app python scripts/commerce_live_snapshot.py
```

输出会给出卷内的 `backup`、`restored` 路径、完整性和内容比较结果。它不替换运行库，也不重置账号、订单或库存。每次执行会生成新文件。

备份包含账号、地址和会话等数据，应与只含摘要的验收报告分开保存。需要真正恢复工作库时，先停止服务、保留旧库及相关文件，再将备份恢复到新目标并验证后切换配置。不要在使用说明之外直接覆盖运行中的数据库，也不要删除Docker卷来代替停止服务。

## 11. 常见问题

| 问题 | 检查与处理 |
|---|---|
| 页面打不开 | 确认Docker Desktop已启动，运行`start --skip-build`和`status`，使用8031入口 |
| 源码改了但页面没变化 | 运行`local-commerce.cmd start`重新构建；已有镜像启动不会加载宿主机源码修改 |
| 卖家有商品，买家没有 | 核对同一实例和店铺、商品是否published；草稿/已下架商品不展示，再刷新商城 |
| 选了某品类，却没出现新商品 | 品类只是分析范围；还需创建候选、通过决策、生成草稿、入库和上架 |
| 不能创建候选 | 等待主题加载；加载失败时重新分析，不要沿用其他品类的旧主题 |
| 不能生成草稿 | 决策须为GO；查看缺失成本、风险标记和利润结果 |
| 入库后仍不能购买 | 还需上架；若原商品已被版本替换，检查是否操作了旧SKU |
| 调价后原商品价格没变 | 新决策不会自动改旧商品；按第8节执行版本替换 |
| 替换版本被拒绝 | 检查待支付预留、可售库存、同候选关系及新草稿是否已入库/售卖 |
| 加购或结算提示库存变化 | 刷新商品与购物车，调整数量或移除失效商品；购物车不保库存 |
| 下单报错，但不确定是否成功 | 先刷新订单核对，再决定重试；不要直接当作失败重新买一遍 |
| 下单后一直pending | 买家在商城 Your orders 点击 Pay … (simulated)；超时后取消并重新下单 |
| 无法发货 | 订单须paid，且不能有待审核退款；先完成审核 |
| 退款后库存没有增加 | 已发货/完成退款不自动回库存；先确认是否真的可再次销售 |
| 申请显示rejected，订单却refunded | 先前申请被拒绝，后来卖家主动退款；分别查看审核说明和最终执行状态 |
| 净损失保存冲突 | 已有记录不能覆盖；不要反复提交不同金额，保留原记录核查 |
| 突然要求重新登录 | 刷新并重新登录同一8031实例；不要混用开发端口会话；已有密码不会被初始化重置 |
| 出现请求过于频繁提示 | 注册、登录或结算触发限流，按页面/响应提示稍后重试 |
| 工作台操作按钮禁用 | 核对角色、主题是否加载、订单状态和店铺匹配；本地owner与受保护配置不要混淆 |
| 汇总与筛选订单金额不同 | 汇总为累计全量，筛选仅影响订单列表；先统一比较口径 |

## 12. 推荐的一次完整练习

1. 在8031登录买家，保存虚构地址，购买已有的一件演示商品。
2. 买家在商城完成模拟支付，卖家按同一订单ID刷新、发货并完成；买家刷新确认。
3. 查看订单来源和经营复盘。
4. 买家提交整单退款，卖家审核并记录净损失，理解已发货退款不自动回库存。
5. 新建自己的候选，使用明确的模拟成本，通过GO后入库上架。
6. 保存同候选的新售价决策，执行商品版本替换，比较新商城价格与旧订单价格。
7. 执行业务一致性检查，最后用`stop`正常停止；下次启动确认数据仍在。
